# Bloom - C++ Modding API for Plants vs. Zombies

Bloom is a project that aims to revolutionize Plants vs. Zombies modding by allowing players to have more than one mod at a time, contrary to the current "decomp" forking model.

Each mod is an independent C++ project that does not modify the game's source and is loaded by Bloom at runtime.

## Principles

Mods should easily add content and modify both vanilla and each other in depth without incompatiblities. For example, it should be possible to make a plant food mod without special casing a plant food ability for every vanilla plant, and instead just doing something based on what kinds of *behaviors* the plant has, eg. speeding up its shooter behavior or giving its projectiles an effect that makes them bigger.

## Progress

### Mod Loading
Done but very simple, no mod loading screen yet for example.

### Custom Resources
Images done, sounds and fonts untested but probably done. Reanims and particles not yet.

### Custom Store Items
Done but not very useful. Will be more useful with the addition of custom plants and non-store items in the future.

### Custom Projectiles
Almost done. Not every vanilla edge case will be able to be replicated by Bloom at first though, same for all other custom content.

### Other Custom Content
Content will be made "custom" (able to be added and modified by Bloom) in this order:
1. Store items
2. Projectiles
4. Zombies
5. Minigames
6. Adventure levels
7. Non-store items (eg. shovels, hammers, plant food from PvZ2)
8. UI buttons
9. UI pages

## Other Plans

### Patches
The standard way to modify content. All they do is give you a non const reference to the type (eg. ProjectileType) object so that you can change attribute values and add/remove/modify behaviors.

### Injections
Injections will allow mods to modify every function in the game, similarly to Minecraft Java mixins, but since they'll modify assembly instead of Java byte code, they'll probably only be able to inject at the start of a function. I don't really know how exactly I'll do this yet but all of the assembly should hopefully be abstracted away and modders will only need C++.

### Automatic Zombotany Generation
Zombotanies will eventually be automatically generated by copying the plant's behaviors into a new zombie type and also gathering the plant's head (mods will be forced to say where their plants' head is) and putting it on the zombie.

## ResoddedFramework

Bloom is based on the [ResoddedFramework](https://github.com/LawnProject/ResoddedFramework) modding base for Plants vs. Zombies. Special thanks to [Electr0Gunner](https://github.com/Electr0Gunner) and the rest of the ResoddedFramework developers.
